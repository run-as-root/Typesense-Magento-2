# Changelog

All notable changes to this project are documented in this file.

## [Unreleased]

### Added

- Header search with Typesense autocomplete (handle `typesense_autocomplete`, added on every page by `LayoutLoadBefore` while the module and autocomplete are enabled): it sets the `header-search` block's template to `search/form-mini.phtml`, a GET form to `catalogsearch/result` (input `#search`, focused on Hyvä's `search-open` window event, Magento's min/max query length) with the Alpine CSP component `typesenseHeaderSearch`. One multi search covers products (plus the synonym-free copy for "Show Direct Matches First"), query suggestions, categories and CMS pages; each side section has its own count (Stores > Configuration > TypeSense > Autocomplete) and is only searched while its entity is indexed. New "Group Products By" setting: a faceted product field sent as `group_by` (`group_limit: 1`, counted with `found_docs`); ignored when the field is not in the product schema or not faceted. Matches are highlighted from Typesense's `<mark>` snippets split into text segments rendered with `x-text` (never `x-html`; follows "Highlight Matches" in the Search settings). The dropdown has "See all (N)" and a no-results line, keyboard navigation (arrows, Enter on a row, Escape closes only the dropdown), a 300 ms debounce, a stale-response guard, and on any Typesense error it hides while Enter still submits the form. Prices use `hyva.formatPrice` and follow the new `AutocompleteConfigViewModel::canShowPrices()` (plug it like the listing's). Dropdown sections are child blocks (`typesense_suggestion`, `typesense_product`, `typesense_category`, `typesense_page`, `typesense_see_all`). Product searches request only the fields the dropdown and GA4 items read (`include_fields`: id, name, sku, url, image_url, final_price, price and the group-by field); the list comes from the new `AutocompleteConfigViewModel::getProductFields()` (config key `productFields`), so a theme that shows more document fields adds them with an after plugin on that method. The handle overrides Hyva_SmileElasticsuite's header search: the module is now sequenced after `Hyva_Theme`, so the handle is merged after `hyva_default`; Elasticsuite's autocomplete scripts are removed from the page. Breaking for customisations: `search/autocomplete.phtml`, `search/direct-matches.phtml`, `web/css/autocomplete.css` and the `typesense.autocomplete`/`typesense.direct.matches` blocks are removed; `AutocompleteConfigViewModel::getConfig()` no longer carries connection settings or the API key (requests use `window.runAsRootTypesense.getClient()`), and its constructor takes `Magento\Search\Helper\Data` and `ProductSchemaProviderInterface`.
- Tracking as window events: the listing dispatches `typesense:results` (now with `stateKey`, the serialized URL state, and `documents`), `typesense:sort-change` (`{context, listName, sort, previous}`) and `typesense:filter-change` (`{context, listName, added, removed}` of `{field, value}`, price as `min-max`) on shopper changes only, tiles dispatch `typesense:select-item` (`{item, index, listName, document}`, not for the no-results suggestions) and the header search `typesense:suggestion-click` (`{type, term, name, url, index, item?}`). New setting Stores > Configuration > TypeSense > Tracking > "Push GA4 Events to the dataLayer" (default off) renders `tracking/ga4.phtml`, which maps them to `view_item_list` (once per listing state, never for empty results), `select_item`, `search_suggestion_click`, `sorting_interaction` and `filter_interaction`, each preceded by `{ecommerce: null}`; GA4 items leave out the price when prices are hidden or the price is 0 (no salable price). `listing-core.js` is now included once per page, in the head, by the `typesense.listing.core` block (`js/listing-core.phtml`), which renders only when a handle sets its `is_required` argument (`typesense_listing`, `typesense_autocomplete`); templates no longer include the script themselves. Header-search and suggested-product requests never count as list views.
- Filter bar, sorting and page size for the storefront listing (`filters` and `toolbar` slots, templates under `listing/filters/`): from `md` up a chip row with one popover per facet (one open at a time, closed by a click outside or Escape), below `md` a drawer (backdrop, scroll lock, focus trap, `inert` while closed, "Show N items" and Reset, sorting as a radio list inside). Facets are routed by type: dropdowns (multi-select with counts, active badge, the first `visible_values` (5) values plus More/Less, and for searchable facets a value search sent as that facet's `facet_query`), one popover for boolean checkbox facets (label from the layout argument `group_label`, default "Properties"; each sends `true`), the price slider (range and number inputs inside the price facet stats, applied on change and clamped, formatted with `hyva.formatPrice`, not rendered when `showPrices` is off) and, on category pages, a subcategory filter from the `categories.lvlN` counts of the next level below the current category (`Model\Listing\SubcategoryFacetResolver`; it replaces the other `categories.lvl*` facets there). Active filters show as chips with Clear All; every change goes to the listing as a `typesense-filter-change` event with a structured detail (`{field, value, action}`, `{field, facetQuery}`, `{price}` or `{clear: true}`), so values containing `-`, `|` or commas are added and removed correctly. Sorting is a listbox on desktop; category pages offer only the options matching the category's "Available Product Listing Sort By" (all options when none match). Page size uses the catalog's grid values. Skeletons (chip widths from the `filter_chip_widths` argument, sort and page size) show until the first result, and the filter bar and toolbar are hidden only once a result is known to be empty without active filters. Components consume the listing's `typesense-state` event through the new `typesenseListingState()` mixin. A facet value search requests only that facet's own search (no grid overlay, no history entry); a full request started meanwhile drops its response. Price is now always the only slider facet (the listing state holds one price range); other facets configured as slider fall back to a dropdown. Facets on numeric fields (`int32`/`int64`/`float`, also arrays; listing config `numeric` holds that type, else `false`) are filtered unquoted (`field:=[4,2]`, Typesense rejects backtick-quoted numbers with a 400) and accept only numbers that fit the type (whole numbers within the int32 or int64 range, plain decimals for float), from the URL and in `filter_by`. A facet value search on one facet no longer drops another facet's pending one. When `ListingConfigViewModel::canShowPrices()` is false, the `price` URL parameter is ignored (not read, not written, not filtered) and price sort options are removed. Rebuild the Hyvä theme CSS after upgrading.
- Storefront listing for the search page and Typesense category pages (handle `typesense_listing`, Alpine CSP components `typesenseListing` and `typesenseTile`), replacing `search/results.phtml` and `category/typesense-listing.phtml`. It is built from child-block slots a theme can override one by one: `filters` and `toolbar` (empty containers for the filter bar and sorting), `ai-answer`, `products-count`, `loading-overlay`, `grid` (with `skeleton` and `tile`), `no-results` (with its own `tile` tree for suggested products), `pagination`, `script` and `json-ld`; each tile has the slots `image`, `badges`, `wishlist`, `rating`, `price`, `variants` and `actions`. Behaviour: server-rendered skeleton tiles (`placeholder_count`, default 8) until the first result, a loading overlay on refetch, the first `eager_load_images_count` (default 4) images loaded eagerly with `fetchpriority=high`, a products count, a numbered pagination window with real links, URL state written through the listing core (replace on first load, push on user changes, refetch on back/forward, stale responses dropped), an error state ("Search is temporarily unavailable") when Typesense fails, and a no-results message that depends on the page and active filters, optionally followed by products of a configured category. Tiles show a "New" badge, rating stars (`Intl.NumberFormat` with the store locale), prices via `hyva.formatPrice` (never a price of 0), grouped children with a quantity per child, add to cart as a POST to `checkout/cart/add` with form key (`qty=1`, or `super_group[childId]` for grouped products) and a wishlist button (`wishlist/index/add`, marked from the `wishlist` customer section). Category pages write an ItemList JSON-LD (`#typesense-item-list`) after every request. After each render the listing dispatches `typesense:results` (`{context, listName, page, items}` as GA4 items) and `typesense-state`, and it listens to `typesense-filter-change`, `typesense-sort-change`, `typesense-limit-change` and `typesense-page-change`. `ListingConfigViewModel::canShowPrices()` (default true) hides prices on tiles, in the JSON-LD offers and in the GA4 items when a project plugs it to false. New settings under Stores > Configuration > TypeSense > Instant Search Result Page: "Facet Types" (dropdown/checkbox/slider and value search per facet; price defaults to a slider), "Show Out-of-Stock Products Last" (default yes), "No Results: Suggested Products Category ID" and "SEO Text Selector" (default `.page-bottom .category-description`, hidden on pages after the first). "Facet Filters" now also offers Price, Availability and New. The module registers itself for Hyvä's Tailwind build (`hyva_config_generate_before`). Product documents get `is_new` (bool facet) from "Set Product as New From/To", evaluated at index time. Upgrade note: run a full product reindex for `is_new`, and rebuild the Hyvä theme CSS.
- Listing core (`view/frontend/web/js/listing-core.js`, exposed as `window.runAsRootTypesense.listing`): the dependency-free logic the storefront listing builds on, unit-tested with `node --test` (`npm test`, CI job `js-unit`). Filters are backtick-quoted exact matches (values containing a backtick are dropped, booleans are `field:=true`, price is `price:[min..max]`); facet counts are disjunctive (one `per_page: 0` search per filtered facet without its own filter, carrying that facet's value search as `facet_query`, plus one search for the remaining facets), and every search, including category facet searches, carries the store's search and cache parameters. Sorting can put out-of-stock products last (`in_stock:desc` first, at most three sort fields). URL state uses `q`, `page`, `sort`, `limit`, `price` (`min-max`) and one parameter per facet (values percent-encoded one by one and joined by `|`); only these keys are read, invalid sort/limit/page values fall back to the defaults, and defaults are left out of the URL. Also: history replace/push decisions (no duplicate entry on first load), a sequencer that discards stale responses, the pagination window, page clamping, ItemList JSON-LD (AggregateRating only with reviews), GA4 items and error normalisation. `reorderByDirectMatches` moved here unchanged (the old `window.runAsRootTypesense.reorderByDirectMatches` global is removed; use `window.runAsRootTypesense.listing.reorderByDirectMatches`). Boolean facets (facet type `checkbox` or `boolean: true` in the listing config) accept only `true`/`false`, from the URL and in `filter_by`, so a hostile `?in_stock=foo` is ignored instead of failing the listing with a Typesense 400; facet values ending in a backslash are dropped too. `buildSearches()` reports which search holds each facet (`searches.facetSources`, not sent to Typesense) for `mergeFacetCounts`/`facetStats`. `price` is now a facet field (for the price slider's min/max stats and so a `facet_by` list containing `price` no longer fails); `in_stock` is declared sortable explicitly (Typesense already sorts bool fields by default). Upgrade note: run a full product reindex for the `price` facet.
- Lighter Typesense pages: one shared `window.runAsRootTypesense.getClient()` (a promise of a single `Typesense.Client`, `connectionTimeoutSeconds: 10`, search-only key) replaces the per-template typesense-js `<script>` tags; it injects the pinned jsDelivr `typesense@1.8.2` build with SRI once, on `DOMContentLoaded` on search/category listing pages and on the first focus or hover of the header search input elsewhere. A `<link rel="preconnect">` to the search node is added to every page while the module is enabled. On Typesense category pages (`typesense_category_search` handle) and on the instant search page, every `ListProduct` block gets an empty collection before `getLoadedProductCollection()`, `toHtml()` or `getIdentities()` can build or load Magento's product listing (`Promotion`/`Random` product lists are excluded; a `ListProduct` embedded in CMS content on such a page renders empty too). New "Cacheable Search Page" (Stores > Configuration > TypeSense > Instant Search Result Page, on by default): the search page is served as a full-page-cacheable shell without the core search controller when its URL holds only `q`, `page`, `sort`, `limit`, `price` and configured facet parameters (any other parameter gets the uncached core page, so junk parameters cannot flood the cache). Search terms are still logged: the cached page calls core's `catalogsearch/searchTermsLog/save` from the browser, so popularity and the Search Terms report keep updating; only `num_results` is not written. Terms with a redirect URL still redirect. The search page title is "Search Results" and becomes "Search results for: '…'" from `?q` in the browser.
- Listing-ready index data: `image_url` is now a resized, cached image built with the Magento image id from Stores > Configuration > TypeSense > Instant Search > Image Type (default `category_page_grid`; the previous `image`/`small_image`/`thumbnail` options are replaced by image ids, and a stored legacy or unknown value falls back to `category_page_grid` automatically), and multiselect additional attributes are indexed as `string[]` label arrays (schema type `string[]`, still faceted). `LayoutLoadBefore` keeps the Magento category page for categories with display mode "Static block only". Upgrade note: full product reindex required; without Zero-Downtime Reindex delete the product collections first (`typesense:collection:delete`) because field types change.
- Grouped listing data, salable stock and price fields: product documents get `final_price` (equals `price`) and `regular_price`; `in_stock` now comes from MSI `IsProductSalableInterface` for the stock of the store's website (the module requires the Magento Inventory modules). Grouped products get `children[]` (`id, sku, name, final_price, regular_price, in_stock, qty_increment`, link position order, not indexed), `in_stock` = any child salable, and the prices of the cheapest salable child (of the cheapest child when none is salable); a grouped product without enabled children is not indexed and its document is deleted on the next partial reindex. `special_price` is removed (use `regular_price` > `final_price`, which respects the special-price dates). Product collections are created with `enable_nested_fields` (entity indexers can add collection settings via `Api\CollectionSettingsProviderInterface`). Breaking for customisations: `PriceCalculatorInterface::getSpecialPrice()` is replaced by `getRegularPrice()`, `StockResolverInterface` is replaced by `Resolver\SalableResolverInterface`, and `ProductDataBuilder::build()` returns `null` for products that must not be indexed. Upgrade note: full product reindex required; without Zero-Downtime Reindex delete the product collections first (`typesense:collection:delete`), because nested fields can only be enabled when a collection is created.
- Active boosting rules now apply to relevance sorting on the search page, in autocomplete and on Typesense category listings: `sort_by` becomes `_text_match(buckets: N):desc,_eval([(<rule filter>):<weight>, …]):desc`, with the store's active, in-window rules for that context. Rules reorder products only within a text-match bucket; "Boosting Rule Text Match Buckets" (Stores > Configuration > TypeSense > Search, default 10) sets N. A rule whose conditions fail to compile, whose condition values contain parentheses (Typesense's `_eval` parser cannot read them), or whose conditions use an attribute not in the store's Additional Attributes (Typesense rejects unknown fields in `_eval`, failing every search) is skipped and logged as a warning. Saving a rule with parentheses in a condition value shows a warning; saving one on an attribute that is not indexed is rejected. Saving or deleting a rule cleans the full page cache.
- Boosting rules (Stores > TypeSense > Boosting Rules): per store view or all store views, with a non-zero weight (positive boosts, negative demotes), an optional date window, search and/or category listing scope, and product conditions built with the virtual-category condition builder (limited to the same Typesense-filterable attributes). Upgrade note: run `setup:upgrade` for the new `run_as_root_typesense_boost_rule` table and grant the new "Boosting Rules" ACL resource to restricted admin roles.
- "Show Direct Matches First" (Stores > Configuration > TypeSense > Search, on by default): products matching the query itself are ranked above synonym-only matches on the search page and in autocomplete, via a second search with synonyms disabled in the same multi-search request. `found`, facets and pagination still come from the synonym-enabled search. The search page now uses `multiSearch.perform()`, so the server-side cache parameters are sent as request options instead of being merged into the search parameters.
- German decompounding (Stores > Configuration > TypeSense > Search, per store): products get a `name_decompounded` field with the tails of German compound words ("Treppensackkarre" -> "Treppensackkarre Sackkarre Karre"), searchable once it is given a weight under Searchable Attributes (add that row only after the full reindex has finished). Words of an optional "never split" product attribute (e.g. a product line) are kept whole. Upgrade note: the module now requires `run-as-root/german-compound-splitter` (add its VCS repository until it is on Packagist, see README); run a full reindex after enabling.
- Configurable infix search (fields and `always`/`fallback` mode) and stemming under Stores > Configuration > TypeSense > Search; the `infix` request parameter is aligned with `query_by`. Stemming applies only to the full-text fields (name, description, short description, categories text, `name_decompounded`); SKU, URLs, `type_id`, category paths and additional (facet) attributes stay unstemmed so their filters match exactly. Upgrade note: both are schema flags, so run a full reindex after changing them (stemming is on by default, so existing installs need one after upgrading).
- Admin-configurable weighted searchable attributes (Stores > Configuration > TypeSense > Search); they drive `query_by` and `query_by_weights` for storefront product searches. Defaults: name (10), SKU (9), description (1).

### Fixed

- A quantity typed into a grouped tile's size row is rounded up to the next multiple of that size's quantity increment (on `change`, written back into the input); a non-multiple was rejected by the cart, which redirected to the product page.
- A malformed "Facet Types" or "Searchable Attributes" config value (not valid JSON, e.g. hand-edited or PHP-serialized) is treated as unset instead of throwing, which failed every listing and search page with a 500.
- A configured facet whose field is missing from the product schema or not faceted (e.g. an attribute removed from "Additional Attributes to Index") is left out of the listing config: Typesense rejected the facet search with a 400, so every other facet disappeared, and with its URL parameter set the whole listing showed the error state.
- The CSP `connect-src` allowlist now includes the search node the browser actually connects to (`general/search_host`/`search_port`/`search_protocol`, falling back to the indexing node) besides the indexing node; with a separate public search host, storefront Typesense requests were blocked under a restrictive CSP.
- Product recommendations ("You May Also Like") are a CSP-safe Alpine slider (`typesenseRecommendations` with one `typesenseRecommendation` per tile) rendered with `x-for`/`x-text`/attribute bindings instead of `innerHTML`, so document names and URLs can no longer inject markup or attributes; prices use `hyva.formatPrice` (no more hardcoded `$`) and follow the new `RecommendationsConfigViewModel::canShowPrices()` (plug it like the listing's). The view model's config no longer carries the Typesense host, port, protocol and key: requests use the shared `getClient()`. Strings are translated in `de_DE.csv`.
- Grouped tiles add the chosen sizes to the cart again: `buildCartParams()` takes the tile's child ids as a fifth argument and sends every child in `super_group`, unselected ones as 0, as the product page does; Magento answered a partial `super_group` with "Please specify the quantity of product(s)".
- An additional attribute named like a core product field (e.g. `short_description`, set through a config import that bypasses the admin list) no longer fails the product reindex with "duplicate field names in the schema"; the core field is kept.
- Additional attributes named like any product document field (including `is_new`, `in_stock`, `sales_count`, `category_ids`, `children`, `categories_text`, `name_decompounded` and `embedding`) are no longer offered in the admin, are skipped in the schema and are never indexed: previously a Yes/No `is_new` attribute replaced the core boolean with "Yes" and Typesense silently dropped the product, and a `category_ids` attribute overwrote the category ids. The list is `ProductSchemaProvider::RESERVED_FIELDS`; core values always win over additional attributes in the document.
- Category path facets are hierarchical: each product now carries the path of every ancestor of its categories at that ancestor's level (`categories.lvl0` top-level name, `categories.lvl1` "A > B", `categories.lvl2` "A > B > C" and every deeper path), so a parent category's value counts its whole subtree, as the subcategory filter needs. The store root and root catalog no longer appear in `categories.lvl0`. `category_ids` also holds the anchor ancestors of each assigned category, following Magento's anchor index (an active assigned category adds every active anchor ancestor, also above a non-anchor one; the store root is not added), so Typesense category pages, the category merchandiser and the "No Results" suggested products of an anchor category now list the products of its whole subtree, as Magento does. Category names, paths and anchor membership are read per indexed store (the category cache is per store), and inactive categories add no name and no path (an inactive assigned category adds nothing for its ancestors either; its own id stays in `category_ids`). Upgrade note: run a full product reindex.
- With instant search disabled (or the module off), the search page keeps Magento's own results again: the Typesense search layout moved from `catalogsearch_result_index.xml` to the `typesense_search_result` handle, which `LayoutLoadBefore` adds only while both are enabled.
- A virtual category whose rule contains `||` keeps its merchandising (pins/hides) on the storefront: the listing no longer wraps the category filter in extra parentheses when no facet is active, so `filter_by` equals the override rule again.
- The search page, autocomplete and category listing configs are JSON-encoded with `JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT`, so admin-entered values (e.g. boosting rule conditions containing `</script>` or `<!--`) cannot break the inline script.
- Partial reindexes (mview/`executeList`) no longer build a new collection and swap the alias to it; they upsert into the live alias and skip with a log when no index exists yet.
- Partial reindexes delete documents for entities that are disabled, removed from the store's website, not visible, or deleted; document ids are mapped per entity type (`EntityIndexerInterface::getDocumentId()`), so prefixed ids (customers, orders, stores, config) are removed too.
- Changing a child product re-syncs its parent products (configurable, grouped, bundle) via `catalog_product_relation`.
- Products are indexed only into the collections of stores whose website they belong to; inactive stores and stores with TypeSense disabled are skipped; indexing runs inside store emulation.
- Autocomplete suggestions query the `query` field (previously the non-existent `q`).
- Synonyms and category/query merchandising overrides survive zero-downtime reindexes: they are re-applied to the new collection before the alias swap.
- Category merchandising pins/hides apply again: the storefront category listing and the override `rule.filter_by` are built by one `CategoryListingFilterBuilder` (category filter + `visibility:[2,4]`), since Typesense matches override filters exactly.
- `typesense_product` mview subscribes to `catalog_product_website` and `catalog_product_relation` (`parent_id`), so removing a product from a website or changing a parent's children triggers a partial reindex.
- Product visibility is filtered on the attribute, not via `catalog_category_product_index`, so a stale category index no longer decides what is indexed and products without a category are indexed.
- Every mview indexer ignores an empty id list instead of running a full reindex.
- A store enabled only at store-view scope is indexed even when TypeSense is disabled at default scope.
- A failed zero-downtime build deletes its half-built collection instead of leaving it behind.
- Deleting a synonym removes it from Typesense first; a Typesense failure leaves the stored synonym intact.

### Added

- `run_as_root_typesense_synonym` table; admin synonyms are persisted in Magento and pushed to Typesense.
- `typesense:collection:rollback --entity=<type> --store=<code>` points an alias back to the previous collection version.
- Partial product reindexes go through the `typesense.reindex` message queue when queue reindex is enabled (message carries `entity_ids`).
- Search settings for text match type, drop/typo token thresholds, minimum word lengths for 1/2 typos, exact-match priority, split/join words, prefix search and the Typesense server-side search cache (`run_as_root_typesense/search/*`, store scope; defaults `max_weight`, 0, 1, 5, 8, yes, `fallback`, yes, cache on with 300 s TTL). The search page, autocomplete products and category listings send them from one `SearchRequestParamsBuilder`; "Enable Typo Tolerance" now sets `num_typos` (2 or 0).

### Changed

- `composer.json` now requires `magento/module-inventory-sales-api` and `magento/module-inventory-configuration-api` (`^1.2`; Mage-OS packages replace them), which the product indexer calls for salable stock and quantity increments.
- Breaking for customisations: `ProductSchemaProviderInterface` now extends `Api\CollectionSettingsProviderInterface`, so a custom implementation (preference) must add `getCollectionSettings(): array` and return at least `['enable_nested_fields' => true]` for the grouped `children` field. `ProductEntityIndexer` also implements `CollectionSettingsProviderInterface`; other entity indexers may implement it to set collection-level schema options.
- Breaking for customisations: `ViewModel\Frontend\CategorySearchConfigViewModel` is removed and `InstantSearchConfigViewModel` keeps only `isEnabled()`; the listing configuration comes from `ViewModel\Frontend\ListingConfigViewModel::getConfig('search'|'category')`. `ProductDataBuilder` takes a new `NewProductResolverInterface` constructor argument. `view/frontend/web/css/instant-search.css` and the search page's direct-matches block are removed. Conversational search on the search page now shows its answer above the keyword results; the product grid always comes from the keyword search, so facets and paging stay consistent.
- `openai-php/client` constraint widened to `^0.19 || ^0.20` (installs that already lock 0.20 can require the module).
- Product collections now include "Catalog" visibility; the search page and autocomplete filter `visibility:[3,4]`, category listings `visibility:[2,4]`.
- Zero-downtime cleanup keeps the new collection and the one the alias pointed at before the swap (the rollback target) and deletes every other version. Rollback moves to the highest lower version, or to the other remaining version when none is lower.
- A plain (non-versioned) collection that has the alias name is replaced by a versioned collection + alias on the next full reindex.
- `typesense_product` mview batch size is 200; the reindex consumer processes up to 100 messages per run.
- `EntityIndexerInterface` has a new method `getDocumentId(int $entityId): string` — custom indexers must implement it.
- Removed the unused "Minimum Word Length for Typo Tolerance" setting (`search/typo_tolerance_min_word_length`); use the new per-typo minimum word lengths.
- Removed the unused `view/frontend/web/js/instant-search.js` and `autocomplete.js` (the templates carry their own inline scripts).
- `TypeSenseConfigInterface` has new search-parameter getters, and the instant search, autocomplete and category search ViewModels take `SearchRequestParamsBuilder` and `SearchParametersProvider` as new constructor arguments — custom implementations or subclasses must be updated.

### Upgrade notes

- **Full reindex required** after upgrading (`bin/magento typesense:reindex`): product documents are now website-scoped and include catalog-only products.
- Synonyms that exist only in Typesense (created before this version) are not imported into the new table and will be dropped on the next zero-downtime reindex — re-create them in the admin.
- The one-time plain-collection migration deletes the old collection before creating the alias; if the alias creation fails, search for that store is unavailable until the next successful full reindex.
- `typesense:collection:rollback` does not re-apply synonyms/overrides saved after that version was built.
- A synonym saved while a full reindex is finishing may miss the new collection until the next full reindex.
- Partial product updates via the queue need the `typesenseReindexConsumer` consumer running (`cron_consumers_runner` in `env.php`, or a supervisor-managed `bin/magento queue:consumers:start typesenseReindexConsumer`).
- A failed partial update from the queue is retried up to 5 times (republished with an `attempt` counter); after that the ids are logged and picked up by the next full reindex.
- A rollback target holds catalog data from when it was built; partial updates made since then are missing until the next full reindex.
- An inactive store, or one with TypeSense disabled, keeps its old collection; it is neither updated nor deleted.
- With zero-downtime disabled, stored synonyms are not pushed when a collection is (re)created; re-save them in the admin or use zero-downtime mode.
- Installs without zero-downtime reindex must re-save each category's merchandising once after upgrading so stored overrides get the new listing filter (zero-downtime installs refresh them on the required full reindex).
- **Full reindex required** after changing Enable Stemming, Enable Infix Search, Infix Search Fields, German Decompounding or Never Split Words Of: they change the collection schema or the indexed documents. Stemming is on by default, so upgrading installs need one anyway. Until then, storefront searches fail when the request names something the live schema lacks (a weighted `name_decompounded` row, or infix on a field not yet flagged), so enable German Decompounding, reindex, and only then add the "Name (decompounded)" Searchable Attributes row. These schema changes only take effect with Zero-Downtime Reindex enabled (without it the existing collection is reused; delete it with `typesense:collection:delete` first). Flush the full page cache after the reindex, because cached pages keep sending the old search parameters.
- `run-as-root/german-compound-splitter` is a new dependency. Until it and this module are on Packagist, add both VCS repositories before `composer require` (see README, Installation).
- **Full product reindex required** for the storefront listing (`bin/magento typesense:reindex --entity=product`, Zero-Downtime Reindex on): grouped `children` need `enable_nested_fields`, which Typesense only sets when a collection is created; the same reindex adds the `price` facet (slider stats), sortable `in_stock`, `is_new`, the ancestor category paths in `categories.lvlN` and the anchor ancestors in `category_ids`. Without zero-downtime, delete the product collections first (`typesense:collection:delete`). Until the reindex has run, category pages miss products of child categories and searches that facet on `price` fail.
